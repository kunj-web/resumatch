# Contributing to ResuMatch

Thank you for contributing to ResuMatch.

We follow a professional engineering workflow to maintain code quality and collaboration standards.

---

## Contribution Workflow

1. Fork the repository
2. Create a new branch
3. Make your changes
4. Commit using conventional commits
5. Push your branch
6. Open a Pull Request

---

## Branch Naming Convention

Use meaningful branch names:

feature/user-auth
feature/alumni-directory
bugfix/navbar-overlap
docs/setup-guide
refactor/api-cleanup

---

## Commit Message Convention

Format:

type: short-description

Examples:

feat: add resumatch profile API
fix: resolve login validation issue
docs: update installation steps

Allowed Types:

- feat
- fix
- docs
- style
- refactor
- test
- chore

---

## Pull Request Naming Convention

Format:

type(scope): short description

Examples:

feat(auth): implement JWT authentication
fix(profile): resolve image upload issue

---

## Pull Request Guidelines

- Keep pull requests small and focused
- One feature/fix per PR
- Add screenshots for UI changes
- Update documentation if required
- Ensure tests and lint checks pass

---

## Code Standards

- Follow existing project structure
- Write modular and reusable code
- Avoid unnecessary dependencies
- Use meaningful variable and function names

---

## Before Submitting

Ensure:

- Project runs locally
- No linting errors
- No secrets/API keys committed
- All tests pass

---

## Prohibited Actions

- Direct pushes to main branch
- Force pushing to protected branches
- Large unrelated pull requests

---

Thank you for helping improve resumatch.
